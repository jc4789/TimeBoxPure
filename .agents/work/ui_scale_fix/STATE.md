# Objective
`UIscalefix.md` を、UI内倍率と表示倍率を分離した実装計画へ修正する。今回は実装コードを変更しない。

# Constraints
- `U = 16` はUI座標系の正本であり、既定文字倍率は `1` とする。
- UI内倍率は明示された意味上の倍率だけを扱い、DPI・解像度・空き幅・言語から自動決定しない。
- 表示倍率はUI全体へ一度だけ同率で適用し、入力座標には同じ倍率の逆変換を適用する。
- 表示倍率 `1` を基準かつ有効な結果として残し、DPIだけを理由に拡大しない。
- 画面寸法は領域の配分と配置に使えるが、文字・余白・行高・ボタン内部寸法の個別倍率には使わない。
- 折り返し、文字積み上げ、クリップ、字形生成は今回の倍率修正に含めない。
- Android表示層は決定済み表示倍率を消費するだけとし、原因扱いしない。
- 編集対象は `UIscalefix.md` と、この作業台帳だけ。

# Confirmed Facts
- 現在の最終表示寸法は概念上 `UI寸法 × UI内倍率 × 表示倍率` で決まる。
- `ScaledProceduralRenderer` の `U` は `CANONICAL_UI_UNIT = 16` で、既定文字倍率は `1`。
- 現行 `DisplayScalePolicy` は信頼済み密度を `density × 2` へ変換し、表示倍率を過大にし得る。
- 表示層は全体描画へ表示倍率を掛け、入力を同じ倍率で割っている。この対は維持対象。
- `headingScale(text, maxWidth)` は空き幅によって文字だけの倍率を変えるため、倍率領域を混同している。
- 複数シーンとHUDに、画面比率を文字・余白・行高・部品寸法へ混ぜる式がある。
- 画面比率による領域配分自体はレスポンシブ配置であり、一律撤去の対象ではない。
- 現在の追跡対象ソース差分はなく、計画文書と作業台帳だけが未追跡。

# Rejected Approaches
- 表示倍率そのものを廃止して全画面を常に倍率 `1` に固定する。
- 最終物理画面上でも全解像度で字形を常に16×16画素へ固定する。
- 文字だけをDPI、解像度、空き幅、言語に応じて自動拡大・縮小する。
- 画面比率を使う配置計算をすべて固定寸法へ置換する。
- 折り返しや文字積み上げの変更で倍率問題を隠す。

# Unverified Assumptions
- なし。表示倍率の具体的な採用条件は、計画内で名前付き論理範囲と倍率 `1` 優先として明記する。
