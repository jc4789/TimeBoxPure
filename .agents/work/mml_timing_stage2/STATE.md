# 目的

`timerplan.md` の段階2として、PMD/MMLソフトウェア側のタイミング意味を型で分離する。

# 制約

- 対象は `commonMain` の `audio/mml` 製品コードだけ。
- YM2608、OPNA、物理タイマー、オーバーフロー、IRQの実装には触れない。
- 小文字 `t` は二分音符基準の音楽テンポ、大文字 `T` はタイマーB値の直接指定。
- `C` は全音符内部クロック数、小文字 `c` は音符、`%値` は直接PMDクロック長。
- 既定の音符分母は2分音符。`C96` では、そのクロック消費量を `96 ÷ 2 = 48` と導出する。`48` 自体は音符長ではない。通常音符は `NoteDenominator(2)` のような分母型のまま保持し、消費クロック数だけを現在の `C ÷ 分母` で導出する。`{ec+}4` では末尾の `}4` がその和音の分母を4へ上書きする。`%48` はその音符だけ `C` の分母計算を使わない `DirectPmdClocks(48)` であり、2分音符と同一視しない。
- `#BPM` と `#PMDCLOCK` の後方互換を新設しない。既存挙動を変える必要が判明した場合は変更前に止める。
- テスト、監査、診断、検証は作成も実行もしない。Gradleから連動する `opnaAudit` も禁止対象として扱い、以後ビルドコマンドも実行しない。
- 既存の `audio/opna` の未コミット変更には触れない。
- `timerplan.md` と外部説明資料は根拠であり、変更対象ではない。
- タイミング意味の参照資料は、ユーザー指定の Gemini 説明3ファイルだけに限定する。他の原典、マニュアル、ウェブ資料は参照しない。
