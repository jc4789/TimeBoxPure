# Objective
従来の表示倍率と文字以外のUI形状を維持したまま、表示倍率が文字の物理画素倍率へ直接掛かる経路を分離し、東雲ROMフォントの計測・字送り・描画に共通する文字専用倍率を確立する。文字積み上げ不具合の修正も維持する。

# Constraints
- 文字積み上げ機能は削除しない。
- 文字積み上げを任意指定可能にし、判定を改善する。
- 日本語版の単語「forge」と英語版の同箇所が不必要に積み上がり、ボタン外へ出る問題を直す。
- 英語版メイン画面の「session limit」と「60:00」の重なりを直す。
- DPI・解像度由来の基礎文字拡大と、UI/scenes.kt 側の相対的な過剰拡大を直す。
- `((U * 4) - (U / 4))`、`(U / 2 + U / 8)`、`(U + (U / 2) + (U / 8))` は意図された正しい U の使用法として維持する。
- 固定解像度、縦横判定、端末固有分岐を導入しない。
- 指示されていない機能、テスト基盤、診断コードを追加しない。
- ユーザーが今回、具体的な実機回帰の再現・修正に必要な一時テストと数式オラクルの作成・実行を明示許可した。
- 製品コード変更前に関係ファイルを全文で読み、正確な挙動・根拠・変更許可一覧・最小変更案を提示して承認を待つ。
- この台帳はコミットしない。

# Confirmed
- 基準単位は東雲ROMフォントのグリフセル `U = glyphWidth = glyphHeight`。
- マクロ配置は U の整数倍・整数分割、細部は許可された U / 8 の用途に従う。
- DPIは助言値であり、妥当性検証後に表示寸法から論理寸法と最終変換を確定する。
- コミット `shit` は `30f0b34b6e5b23402659fb249da78f7540c818af`。
- 現行 `DisplayScalePolicy.deriveScale` は信頼済み密度の場合 `(platformDensity * 2f).toInt()` から開始する。
- 現行 `ProceduralTextRenderer.headingScale` は空き幅によって見出し倍率2と1を自動切替する。
- 現行 `ScaledProceduralRenderer.drawButton` は左右 U / 2 を除いた領域で全ボタン文字を無条件に折り返す。
- 現行中央表示は `sessionLimitLabel` を `drawWrapped` で無条件に折り返す。
- Android表示層は描画に `scale`、入力に `1 / scale` を使って対称であり、境界自体は維持対象。
- `FORGE` は 5U=80 に対し現行ボタン文字領域が 76、固定ボタン高が26、強制折返し高が32となり上下3論理pxずつ逸脱する。
- 英語 `SESSION LIMIT` は2U高となり、`dual.5` の固定中心配置で直前の `60:00` と U/2 重なる。
- 見出しは `headingScale` が翻訳後の幅から倍率2/1を選ぶため、英語だけ本文と同じ倍率1になる。
- 1080幅で表示倍率を1へ下げると通常字形は16x16物理画素になるが、文字以外のU基準形状も同時に縮み、既存UIの比率を破壊する。
- ユーザーが承認済みの製品コード変更許可一覧は `EngineCanvas.kt`、`ProceduralUiPrimitives.kt`、`ScaledProceduralRenderer.kt`、`NestedTimeboxInstrumentRenderer.kt`、`Scenes.kt` の5ファイル。
- 提示画像の端末は Google Pixel 10、422 PPI。PPIはAndroid正規化密度係数と同一視せず、端末固有分岐には使わない。
- `drawButton` は固定高の既定一行経路と、明示 `allowTextStacking = true` の可変高経路に分離した。
- `FORGE` は既存の幅・高さ式を維持したまま明示非積み上げにした。
- 全見出しは測定・描画とも `TEXT_SCALE_HEADER` を明示し、言語依存の倍率選択を撤去した。
- 中央ラベルは時刻下端から U / 2 の余白を取る上端基準配置にした。
- `git diff --check` 成功。追跡対象の変更は承認済み5ファイルだけ。新規ホット経路割当て候補なし。
- 変更後の実機画像では、U基準の文字・アイコン・線が約1/3になった一方、画面比率由来のカード・設定行等は巨大な物理寸法を維持し、単位系が分離している。
- 魔法陣は同じAndroid全体変換を共有し、外径はプレイ領域比率、内部詳細はU基準なので、表示倍率変更で内部と外径の相対比が変わる。
- 422 PPIでは16物理pxは約0.96mmであり、提示倍率1は実機で読めない。
- 接続端末の `wm size` は1080x2424、`wm density` と `ro.sf.lcd_density` は420。Android正規化密度は2.625である。
- 旧式は倍率3（360x808）、現差分は末尾正規化により倍率1（1080x2424）。表示倍率の変更自体を文字問題の修正には使わない。
- 魔法陣外半径は幅比率により全倍率で486物理px。中心核は倍率3/1/2で144/48/96物理pxとなるため、外径ではなくU基準内部層だけが崩れた。
- 画像測定で `FORGE` 枠は259x26物理px、テンプレートカードは309px高、設定行は247px高、Entropy入力・タスク行は147px高。現行式の計算値と一致する。
- 表示倍率を `D`、文字の物理ラスター倍率を `P`、意味上の文字倍率を `S` とすると、文字の論理セルは `G = U * S * P / D`、最終物理セルは `U * S * P` となる。計測・字送り・行高・折返し・カーソルは全て同じ `G` を使う必要がある。
- Pixel 10で従来の `D = 3` を維持し `P = 2` とすると、通常文字は32x32物理px、見出しは64x64物理pxになる。非文字UIは従来寸法のままである。
- 現行Androidは通常矩形を論理整数へ丸めてから全体を `D` 倍するため、既存矩形APIへ `P / D` を渡すだけでは `D = 3` 中の2物理px字画を表現できない。
- 最小境界は、共通コアが `P` と全文字メトリクスを所有し、`EngineCanvas` の汎用物理整数矩形を通じて字画を発行し、Androidは方針を持たず提示だけを行う形である。
- 手動字送り・カーソル同期の追加対象は `Scenes.kt`、`NestedTimeboxInstrumentRenderer.kt`、`EngineCursorRenderer.kt`。Settings `layoutRow` は分岐内で単一 `maxRowHeight` を決め、最後に一度だけ `currentY` を進める必要がある。
- 従来の表示倍率導出とAndroid全体変換を復元・維持し、Pixel 10では `D = 3` となる。
- 共通コアの文字専用倍率を `P = minOf(D, 2)` として実装し、`D = 3` では通常文字32x32物理px、見出し64x64物理pxとした。
- 計測・字送り・行高・折返し・カーソルを共通文字メトリクスへ統一し、字画は整数物理矩形として提示する。
- 魔法陣の装飾用極座標グリフは従来のcanonical描画経路へ残し、文字以外のUI形状も変更していない。
- Settings行は分岐内で単一の `maxRowHeight` を算出し、末尾で一度だけ `currentY` を進める形へ修正した。
- 一時数式オラクルで旧48px経路の失敗と新32px経路の成立を確認した。一時共通テストで2x2物理字画、32pxセル、64px見出し、装飾グリフの従来経路を確認し、両方とも削除した。
- `:shared-engine:testDebugUnitTest` と `:app:assembleDebug` は成功した。

# Rejected
- 文字積み上げ処理の削除: ユーザーが明示的に禁止。
- U の指定合成表現の簡略化・置換: ユーザーが意図された表現と明示。
- `UIscalefix.md` のDPI整数値を倍率上限にする案: 2400幅・density 1.5で論理幅1200上限へ到達できない。
- `UIscalefix.md` の積み上げ非変更: 今回の明示依頼と衝突。
- Android Canvas/input変換の変更: 現行は対称で、原因は最終倍率の選択側。
- 1080幅なら無条件に最終倍率1が正しい: 変更後実機画像で可読性とUI比率が明確に悪化したため棄却。
- 表示倍率を2へ変える案: 文字だけの問題に対して文字以外のUIと魔法陣まで変えてしまうため棄却。
- 画面比率由来のカード・設定行・魔法陣を補正する案: 問題のない非文字UIへ変更範囲を拡張するため棄却。
