# 目的

`timerplan.md` の段階3として、解決済みPMDクロック位置をYM2608タイマーBの物理周期からサンプル境界へ変換する。

# 制約

- 使用する外部タイミング資料は、ユーザー指定の3ファイルだけ。
- 洗練版の訂正を優先し、小文字 `t` は二分音符基準の音楽テンポ、大文字 `T` はタイマーB直接値とする。
- オーバーフローはYM2608側だけの物理概念。タイマーBのオーバーフロー1回がPMD演奏時刻の1クロックを進める。
- `C` は全音符PMDクロック数、`c` は音符、`%値` は直接PMDクロック長であり混同しない。
- `#BPM`、`#PMDCLOCK`、固定480刻みの後方互換を段階3の根拠にしない。
- 対象は `commonMain` の音響製品コードだけ。画面、プラットフォーム、ミキサー、音量、音色、楽曲本体は変更しない。製品曲の廃止ヘッダーだけを新しい時間指定へ移行する。
- テストは作成も実行もしない。外部資料、インターネットも追加参照しない。
- ユーザー変更済みの `timerplan.md` は変更しない。

# 確認済み

- `timerplan.md` は634行すべて読了した。
- 指定3資料はコードページ932として全文読了した。
- 洗練版は旧説明の大小文字を明示的に訂正している。
- 8MHz、`C192`、`t80` はタイマーB値202へ量子化される。
- タイマーB値202の物理周期は7.776ミリ秒で、4分音符48クロックなら約160.75 BPMになる。
- 各物理オーバーフロー／割り込みがPMD演奏時刻を1クロック進める。二分周案は誤り。
- 現在の作業ツリーでユーザー変更は `timerplan.md` の1行だけ。
- 現行 `MmlCompiler` はPMDクロックを全音符1920・四分音符480の設定用格子へ拡大している。
- 現行 `PmdSampleClock` はBPMと四分音符480刻みからサンプル境界を作っている。
- 現行 `CompiledOpnaSong` は型付き `t` / `T` / `C` を保持するが、解決済み `T` はサンプル境界へ使われていない。
- 現行 `OpnaTimerB` は `Lfo.kt` 内にあり、`OpnaChipState` が所有する。段階1の物理周期処理は存在するが、製品MML経路ではまだ通知を消費しない。
- 現行 `CompiledOpnaPlayer` は `TEMPO` 大域イベントを通常LFO・包絡の暫定BPM状態へ渡す。段階4まではこの経路を温存する必要がある。
- `SongCatalog` の製品曲はBad Appleだけ。LOGOは製品カタログにない。
- 通常長、`%値`、`Q` / `q`、ポルタメント、FMスロット遅延は整数PMDクロック座標へ移行した。
- 小文字 `t` はその時点の `C` を用いてタイマーBへ量子化し、大文字 `T` は直接タイマーB値として、同じ解決済み変更列へ格納する。
- サンプル境界は、8MHzを分母として各タイマーB周期を整数余り付きで積算する。変更位置そのものまでは旧値、位置後は新値を使う。
- タイムラインは初期タイマーBと曲中変更を大域制御として出力する。再生時に物理タイマー通知へ接続する作業は段階4へ残した。
- 製品曲Bad Appleの廃止済み `#BPM` / `#PMDCLOCK` ヘッダーを `#Tempo 80` / `#Zenlen 192` へ移行した。楽曲本体は変更していない。
- `#BPM` / `#PMDCLOCK` の解析経路と固定480刻みは製品経路から除去した。
- `:shared-engine:compileDebugKotlinAndroid -x :shared-engine:opnaAudit` は成功した。
- `:shared-engine:compileKotlinWin -x :shared-engine:opnaAudit` は成功した。
- テストは作成も実行もしていない。人間による聴取も未実施。

- 小文字 `t` をタイマーB直接値、大文字 `T` を音楽テンポとする旧説明。洗練版で訂正済み。
- 固定480刻みや `#BPM` 互換を正準時間軸に残す案。今回のユーザー指示に反する。
- 段階3で通常LFO・包絡をタイマー通知へ直接接続する案。段階4の範囲である。
- `CompiledOpnaPlayer`、`PmdPerformanceState`、`PmdSoftwareLfo`、`PmdSoftwareEnvelope` を今回変更する案。段階3の境界生成には不要。
